## DD-R06 — leaving a focused mode button loses its formula preview

**Low; DD-24/27/34, A02/A18, M2.**

At this commit, `src/ui/components/modals/RollModalFrame.tsx:39` starts the
preview on focus. Line 47 unconditionally ends it on mouse leave, even when
that same button remains focused. `RollModal.tsx:234`–236 clear the shared
`previewMode` for every end event. Mouse and keyboard state are conflated.

Independent reproduction uses the actual module Tool control and shared modal
in the existing isolated presentation fixture, at widths 1440 and 390:

1. Open the normal-mode Thieves' tools +5 check.
2. Focus Advantage and move the pointer over that button: `2d20kh1+5` appears.
3. Move the pointer out without changing keyboard focus: preview becomes
   `1d20+5`, while Advantage remains the active element.
4. Press Enter: one request submits `2d20kh1+5`.

The selected roll is correct; its displayed preview is misleading. The ordinary
mounted suite passes because it does not combine pointer exit with retained
keyboard focus. This affects the shared numeric modal, not only tool rules.
The [portable result](2026-10-20-c08-c09-review.json) records both observations.
Local reproduction is `/tmp/dnd5e-rv04-focus.mjs`; its result is
`/tmp/dnd5e-rv04-focus.json`. No external request or native connection was made.

Correction: track focus and hover separately. For keyboard activation, preserve
the focused mode preview when hover ends; use the source default when neither
interaction applies. Define a consistent precedence when different buttons are
focused and hovered, so the displayed action and activation agree. Add a mounted
regression for pointer leave with focus retained, focus transfer and restoration
of the source default; preserve manual mode overrides and stale-intent guards.
Keep this a module presentation correction. No rules, Core or SDK change follows.
