## DD-R01 — native die ranges silently lose their meaning

**Severity: medium; functional correction.** Links: DD-02/24/34, A02, M2, Q00.

[prepareNumericSkills606](../../../src/logic/preparation/skills.ts) checks bonus
expressions and advantage modes but omits `min`/`max` from all four applicable
roll scopes. `numericSkillRoll` consequently issues ordinary `1d20+5` even when
the Actor explicitly requires a minimum or maximum natural die result.

Reproduction uses the unchanged `tests/fixtures/native-6.0.6/source-before.json`
and supported context from `src/tests/skills-source.test.ts`. Set one of these
to `{ min: 10 }` or `{ max: 10 }` while retaining the other source fields:

- `system.skills.prc.roll`
- `system.abilities.wis.check.roll`
- `system.rolls.ability.check`
- `system.rolls.ability.skill`

All eight cases still return an available +5 check and `1d20+5`, with no
unavailable reason. This changes possible outcomes: a native minimum of10 should
prevent a natural1 from producing6; a native maximum of10 should prevent a
natural20 from producing25. No effect, optional pack or browser hook is needed
to trigger the discrepancy—these are native stored roll configuration fields.

Exact upstream evidence: `module/data/shared/d20-roll-modification-field.mjs`,
`D20RollModificationField.combineFields`; `module/documents/actor/actor.mjs`,
`_buildSkillToolConfig`; `module/dice/d20-roll.mjs`, `configureModifiers`.
Eight controlled executions of the exact range-combination method return the
configured bound. The oracle stubs only unused field constructors, property-path
lookup and neutral advantage; it does not boot a native runtime or evaluate
effects. This is S evidence, not N.

**Required correction:** Until Q00 qualifies equivalent SDK execution, mark the
affected roll unavailable with a precise reason when a meaningful native range
is configured. Alternatively implement it only with independent range/selection
parity evidence. Do not silently drop bounds or invent a second dice evaluator.
Keep independently known static totals/passives separate from execution readiness
if the view model supports that distinction; a minimum die is not a passive bonus.

**Acceptance:** Test min/max at each scope, absent/null defaults, combined ranges
and malformed inputs. The shared preview, standard/mobile controls, shortcut and
server roll path must agree. A blocked case dispatches no roll; an implemented
case preserves die-range and advantage/disadvantage distributions. Keep source
unchanged. Establish failing-before/passing-after with these same inputs.

## DD-R02 — unavailable context restores incorrect skill rolls

**Severity: medium; functional correction.** Links: DD-01/02/24/31/34, A02/A18,
M1/M2. This is distinct from choosing a supported legacy rule profile.

[DnD5eAdapter.prepareActorData](../../../src/logic/adapter.ts) replaces old skills
only when context is supported and modern. Otherwise it retains the superclass
projection without `derived.skillChecks`.
`getRollData('skill', 'prc')` then takes `system.skills.prc.value` as a total—the
same defect C03 corrected in the supported branch. `derived.lifecycle` reports
unavailable/unsupported, but no current sheet consumer uses it to disable this
fallback.

Using the same Actor, change only the rules context to:

1. `dnd5e.rulesVersion` unavailable (`not-ready`).
2. Native system version `6.0.7`, outside the selected exact profile.
3. No world snapshot.

Each returns **Perception +1 / passive11 / `1d20+1`** instead of a truthful
unavailable state. Static rendering confirms the skill button remains enabled
and has no explanation. The baseline remains +5/passive15. Thus an unavailable
setting or unqualified native version can change displayed math and still permit
a roll. This reproduces the module boundary; it does not claim that every host
disconnect follows this exact path.

**Required correction:** Gate skill preparation and execution on explicit context
readiness. Unknown/unavailable context must not select legacy calculation by
absence of `skillChecks`. Emit consistent unavailable skill/passive values and
reasons, and reject the direct skill roll. Keep genuinely selected legacy behavior
and its qualification limits explicit; do not silently convert legacy data or
broaden native-version support. Audit adjacent numeric domains as scheduled M2
work rather than claiming this narrow correction completes them.

**Acceptance:** Same-input supported → unavailable/unsupported → supported
transitions produce +5/15 → unavailable → +5/15. Confirm both layouts and direct
execution, preserve source and reject stale open intent. Static rendering can
cover the basic control regression; mounted interaction must separately verify
retirement/recovery. No unknown context may revive multiplier-as-total fallback.
